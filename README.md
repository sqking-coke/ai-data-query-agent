# 业务数据智能查询 Agent

## 1. 项目概述

### 1.1 项目背景

传统业务系统中，运营、产品、业务人员查询数据高度依赖后端开发人员写SQL、查数据库、整理报表，沟通成本高、响应慢、重复性工作多。

基于此，本项目**基于Java原生实现轻量级AI Agent**，不依赖重型框架，通过大模型能力实现**自然语言提问 → 自动生成SQL → 数据库查询 → 智能分析生成结论**的全自动化闭环，解决业务数据查询效率低、人力成本高的问题。

### 1.2 项目定位

本项目为**Java后端入门AI Agent标杆项目**，主打原生手写核心逻辑，摒弃开箱即用的框架，帮助开发者彻底理解Agent核心原理：**大模型推理 + 工具调用 + 任务闭环调度**。

可作为个人作品集、面试实战项目，也可改造为企业内部智能数据助手、自动报表系统。

### 1.3 核心目标

- 用户输入自然语言，无需写SQL即可查询业务数据
- AI自动完成意图识别、SQL生成、参数校验、数据查询、结果分析
- 实现多轮会话记忆，支持连续数据问答
- 保障数据安全，内置SQL防注入、非法语句拦截机制
- 轻量化、低耦合、易扩展，可快速叠加更多业务工具

## 2. 需求分析

### 2.1 功能需求

#### 2.1.1 大模型交互能力

- 支持HTTP方式调用通用大模型接口（通义千问、星火、本地大模型均可适配）
- 通过Prompt工程约束模型输出结构化JSON结果，避免自由文本乱输出
- 支持系统提示词、用户对话上下文拼接

#### 2.1.2 AI工具调用能力

- 核心工具：自然语言转SQL工具、数据库查询工具、数据统计分析工具
- 后端自主接管工具执行逻辑，AI仅做决策，不直接操作数据库

#### 2.1.3 Agent调度闭环能力

- 智能判断：无需查库直接回答 / 需要调用工具查询数据
- 工具执行完成后，结合原始问题+查询数据，生成自然语言分析结论
- 支持失败重试、异常兜底、参数校验

#### 2.1.4 会话记忆能力

- 基于会话ID存储多轮对话上下文
- 支持上下文关联提问，实现连续问答

### 2.2 非功能需求

- **安全性**：拦截DELETE、DROP、ALTER等高危SQL，防止SQL注入
- **可用性**：大模型调用超时、数据库异常有兜底响应，不崩溃
- **可扩展性**：工具可插拔，新增业务工具无需改动核心调度逻辑
- **轻量化**：无重型Agent框架依赖，启动快、部署简单

## 3. 整体架构设计

### 3.1 架构模式

采用**分层式轻量级Agent架构**，从上至下分为四层，完全贴合Java后端开发思想，高内聚低耦合。

### 3.2 四层架构详解

#### ① 接入层（Controller）

接收前端用户请求，接收用户提问与会话ID，参数校验，调用Agent核心服务，返回最终分析结果。

#### ② Agent调度层（核心）

整个项目的核心中枢，负责：接收用户问题 → 调用大模型决策工具 → 执行对应业务工具 → 汇总结果二次推理 → 生成最终答案。

#### ③ 工具能力层

封装所有可被AI调用的后端业务能力：SQL生成、数据库查询、数据统计、参数校验、安全拦截。

#### ④ 基础服务层

大模型HTTP客户端、MyBatis数据库操作、会话缓存、异常处理、重试机制。

### 3.3 核心业务流程

**完整Agent闭环流程**：

1. 用户输入自然语言问题（例：查询本月订单总数和异常订单数量）
2. 后端拼接系统提示词+历史上下文，请求大模型
3. 大模型返回结构化JSON：选择工具、生成执行参数、输出思考过程
4. 后端校验参数合法性、拦截高危操作
5. 执行数据库查询工具，获取原始业务数据
6. 将「用户问题+原始数据」再次传入大模型
7. 大模型基于真实数据生成分析结论、报表总结
8. 后端缓存本次对话，返回最终结果给用户

## 4. 核心模块设计

### 4.1 LLM客户端模块

统一封装大模型HTTP调用工具，支持动态拼接Prompt、统一请求参数、超时配置、异常捕获。

**核心能力**：统一模型调用入口、结构化输出约束、请求重试、超时兜底。

### 4.2 工具注册与执行模块

采用枚举统一管理所有AI可调用工具，新增工具只需新增枚举+实现对应方法，无需修改核心调度逻辑。

内置工具：

- 自然语言转SQL工具
- 数据库查询工具
- 数据统计分析工具

### 4.3 Agent调度核心模块

项目核心中枢，实现**思考-行动-观察-总结**的经典Agent闭环：

- 思考：大模型判断是否需要工具、需要什么工具
- 行动：Java后端执行真实业务逻辑
- 观察">获取工具执行结果
- 总结">基于结果生成最终回答

### 4.4 安全校验模块

针对AI生成的SQL做强制校验，拦截高危语句：

- 拦截 DROP、DELETE、ALTER、TRUNCATE 等危险操作
- 防止SQL注入特殊字符
- 限制查询表范围，禁止查询系统表

### 4.5 会话记忆模块

基于内存Map实现轻量级会话存储，存储会话ID对应的多轮对话记录，支持上下文关联问答，后续可无缝升级为Redis持久化。

## 5. 数据库设计

项目采用MySQL，使用模拟业务订单表作为查询数据源，用于Agent数据查询演示。

### 5.1 订单业务表（order_info）

|字段名|类型|说明|
|---|---|---|
|id|bigint|主键ID|
|order_no|varchar|订单编号|
|order_amount|decimal|订单金额|
|order_status|tinyint|订单状态（0异常/1正常）|
|create_time|datetime|创建时间|
## 6. 核心接口设计

### 6.1 Agent智能问答接口

- **请求地址**：/agent/chat
- **请求方式**：POST
- **请求参数**：sessionId（会话ID）、question（用户问题）
- **返回结果**：智能分析结论+数据明细

## 7. 技术栈选型

### 7.1 后端技术栈

- 核心框架：SpringBoot 3.4.x
- 数据库：MySQL 8.0
- 持久层：MyBatis-Plus
- HTTP工具：OkHttp / Hutool Http
- JSON解析：FastJSON2
- 缓存：内存ConcurrentHashMap（可升级Redis）

### 7.2 AI能力选型

- 兼容通用OpenAI格式接口：通义千问、讯飞星火、DeepSeek、本地Qwen均可适配
- 无框架依赖，纯原生HTTP调用

## 8. 核心亮点与创新点

- **原理通透**：不依赖LangChain4j、SpringAI框架，手写Agent核心调度，彻底理解AI Agent运行机制
- **后端主导**：AI只负责思考决策，所有执行、校验、权限、安全全部由Java后端掌控，符合企业开发规范
- **安全可控**：杜绝AI直接操作数据库，层层校验，防止数据误删、注入风险
- **极易扩展**：工具可插拔，可快速新增接口调用、文件生成、报表导出等能力
- **工程化规范**：分层架构、异常兜底、重试机制、参数校验，完全企业级标准

## 9. 项目可扩展方向

- 接入Redis实现会话持久化，支持分布式部署
- 新增RAG知识库，支持业务文档问答
- 接入定时任务，实现自动日报、周报生成
- 扩展多Agent协同：数据Agent、文案Agent、巡检Agent分工协作
- 接入SpringAI重构，简化模型调用逻辑

## 10. 部署与运行方式

1. 创建MySQL数据库，导入order_info模拟数据
2. 配置application.yml数据库连接、大模型API密钥与地址
3. 启动SpringBoot项目
4. 通过Postman/前端页面调用接口，实现智能数据问答

## 11. 项目总结

本项目是**Java后端最适配的入门AI Agent实战项目**，区别于网上纯AI脚本、前端Agentdemo，完全基于Java后端工程化思想开发。完整实现了Agent最核心的「模型推理+工具调用+流程闭环」能力，既能用于入门学习、吃透Agent原理，也可作为高质量简历项目，同时可无缝迭代为企业级智能业务助手。
